# Stockroom Kids

Система учёта товаров, закупок в Китае, себестоимости, складских остатков и продаж розничного магазина детских товаров.

Реализован рабочий MVP: серверная бизнес-логика, база данных, права доступа, документы закупки/приёмки/продажи/возврата, расчёт себестоимости с распределением расходов, отчёты, экспорт CSV и веб-интерфейс для компьютера и телефона.

## Что уже работает

- Каталог: модели, варианты (размер/цвет/исполнение), фотографии, розничные цены и история их изменений.
- Закупки: поставщики, позиции с ценой в CNY, курс и дата курса, статусы, оплаты, дополнительные расходы.
- Приёмка: отдельный документ, частичная приёмка, недостачи и повреждения, проведение с записью складских движений.
- Себестоимость: стоимость товара в рублях по зафиксированному курсу + распределение расходов (по стоимости, по количеству, вручную), взвешенная средняя себестоимость по варианту.
- Склад: остатки из движений, журнал движений, корректировки с причиной, инвентаризация.
- Продажи: корзина, проверка остатка на сервере, скидка в пределах прав, фиксация себестоимости и валовой прибыли, защита от повторной отправки.
- Возвраты: связь с продажей, запрет повторного возврата, возврат в продажу только для пригодного товара.
- Отчёты: остатки, продажи, закупки; экспорт каталога, остатков, продаж и закупок в CSV с учётом прав.
- Администрирование: сотрудники и роли, журнал действий, настройки, резервное копирование.
- Интерфейс: адаптивная вёрстка, боковая навигация на компьютере, карточки и крупные элементы на телефоне, состояния загрузки и ошибок.

## Стек и отличие от первоначального проекта ТЗ

ТЗ предполагало `Next.js + React + TypeScript`, `PostgreSQL` и `Prisma`. В этой реализации использованы:

| Слой | Реализация |
| --- | --- |
| Сервер | Node.js 24, встроенный `node:http`, слой API `src/api.mjs` |
| База | SQLite (`node:sqlite`), WAL, файл `data/stockroom.db`, миграции в `src/migrations` |
| Интерфейс | SPA на нативных ES-модулях, `public/js`, стили `public/styles.css` |
| Авторизация | Серверные сессии в БД, HttpOnly + SameSite=Strict cookie, scrypt-хеши паролей |

Причины: окружение без установленного Node.js на PATH и без сервера PostgreSQL, требование получить работающую систему, а не макет. SQLite выбран как встраиваемая СУБД, не требующая отдельного сервиса.

Что это меняет на практике:

- Один серверный процесс и один файл базы. Для одного магазина и нескольких сотрудников этого достаточно.
- Горизонтальное масштабирование и несколько инстансов приложения не поддерживаются.
- Переход на PostgreSQL потребует замены слоя `src/db.mjs` и синтаксических мелочей в SQL; бизнес-логика в `src/domain` от СУБД не зависит.
- Интерфейс не использует React; структура страниц повторяет разделы ТЗ, поэтому перенос на React/Next.js возможен постранично без изменения API.

## Запуск

Требуется Node.js 24 или новее (используется встроенный модуль `node:sqlite`).

```powershell
# из папки проекта
node src/seed.mjs      # создаёт БД, роли, категории и три учётные записи
node src/server.mjs    # http://127.0.0.1:3000
```

Если Node.js не установлен в систему, можно указать путь к портативной сборке:

```powershell
& "C:\Users\Admin\AppData\Local\StockroomKids\node-v24.22.0-win-x64\node.exe" src/seed.mjs
& "C:\Users\Admin\AppData\Local\StockroomKids\node-v24.22.0-win-x64\node.exe" src/server.mjs
```

Переменные окружения:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `PORT` | порт приложения | `3000` |
| `HOST` | адрес прослушивания | `127.0.0.1` |
| `SRK_DATA_DIR` | каталог файла базы и WAL | `data` |

Для доступа с телефона в той же сети: `HOST=0.0.0.0`. В интернет публиковать только через HTTPS-прокси и сменёнными паролями.

## Android-приложение

Готовый APK: `mobile/apk/stockroom-kids-1.1.apk` (подписан, ~2,8 МБ). Это нативная оболочка (Capacitor) вокруг того же интерфейса: при первом запуске вводится адрес сервера вида `http://192.168.0.104:3000`, дальше приложение подключается автоматически. Функционал, права и данные полностью совпадают с веб-версией.

Сервер для телефона запускается файлом `start-server.cmd`: он слушает всю локальную сеть и печатает адрес для подключения.

Установка: передать APK на телефон, разрешить установку из этого источника, открыть приложение и ввести адрес. Адрес показывается на компьютере в «Настройках → Состояние системы». Подробности сборки, подписи и выпуска обновлений — `docs/android.md`.

## Публикация в интернете через GitHub и Render

В проекте уже есть `Dockerfile`, `render.yaml` и GitHub Actions. Пошаговая инструкция: загрузка через GitHub Desktop, создание сервиса на Render с постоянным диском, учётные записи и проверка синхронизации — в `docs/hosting.md`.

## Доступ из любой точки

Бесплатный публичный адрес: двойной щелчок по `start-public.cmd`. Скрипт поднимает сервер и туннель `serveo.net`, в окне появляется ссылка вида `https://<адрес>.serveousercontent.com` — она работает с любого устройства в России. Пока окно открыто, приложение доступно извне; адрес меняется при каждом запуске. Подробности, ограничения и безопасность — `docs/public-access.md`.

## Правила учёта, заложенные в систему

1. Остаток не редактируется напрямую: он складывается из проведённых движений.
2. Документ проводится транзакционно: движение, остаток и запись документа сохраняются вместе или не сохраняются вовсе.
3. Проведённый документ не удаляется и не перезаписывается: исправление — обратной операцией или корректировкой.
4. Продажа проверяет остаток на сервере; одновременные продажи последних единиц не создают отрицательный остаток.
5. Курс CNY/RUB вводится вручную и хранится в документе; изменение текущего курса не переписывает историю.
6. Дополнительные расходы хранятся отдельно от цены товара и распределяются выбранным методом; сумма распределения всегда равна сумме расхода.
7. Себестоимость — взвешенная средняя по варианту товара; партии и расходы сохраняются для аудита.
8. Оплата поставщику не равна себестоимости поступившего товара.
9. Повторная отправка запроса на продажу, приёмку или возврат не создаёт дубль (идемпотентность по `clientRef`).
10. Все права проверяются на сервере, а не скрытием кнопок.

## Проверка

```powershell
node tests/acceptance.mjs
```

Тест поднимает отдельный экземпляр приложения на временной базе, прогоняет 60 проверок по критериям приёмки ТЗ и удаляет временные данные. Результат последнего прогона — в `docs/acceptance.md`.

Резервная копия:

```powershell
node scripts/backup.mjs     # создаёт backups/stockroom-<дата>.db
```

Порядок восстановления и требования к эксплуатации — в `docs/backup.md`.

## Известные ограничения MVP

- Нет интеграции с кассой и фискализации чеков; продажа в системе не заменяет кассовый чек.
- Нет сканирования штрихкодов, онлайн-магазина, обмена с маркетплейсами и бухгалтерией.
- Курс валют вводится вручную, автоматического получения курса нет.
- Учёт по одному магазину и одному складу; многофилиальность не поддерживается.
- Полноценного офлайн-режима нет: интерфейс требует связи с сервером, при потере сети показывается ошибка.
- Мобильные приложения iOS/Android не разрабатывались; API к ним готов, но публикация требует отдельного этапа.
- Фотографии хранятся в файловой системе `storage/uploads`; объектное хранилище не подключено.
- Встроенная СУБД рассчитана на один серверный процесс.
- Отчёт «движение денег по закупкам» ограничен зарегистрированными оплатами; банковской сверки нет.
