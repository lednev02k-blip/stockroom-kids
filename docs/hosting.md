# Публикация через GitHub и Render

Цель: одно веб-приложение в интернете, одна база, три роли. Все устройства (Россия, Китай, телефон, ноутбук) открывают один адрес и работают с одними и теми же данными — синхронизация идёт через сервер и базу.

## Что уже лежит в проекте

| Файл | Назначение |
| --- | --- |
| `Dockerfile` | образ приложения: Node.js 24, миграции и запуск сервера |
| `render.yaml` | описание сервиса Render: порт, health-check, постоянный диск `/data` |
| `.github/workflows/ci.yml` | при каждом push прогоняет 60 приёмочных тестов, затем дёргает деплой |
| `.gitignore` | не отправляет в GitHub базу, фотографии, ключи и сборки Android |
| `src/migrations/002_users_admin_role.sql` | добавляет роль «Администратор» |

## Шаг 1. Выложить код на GitHub (GitHub Desktop)

Git в системе не установлен, поэтому проще через приложение:

1. Установите [GitHub Desktop](https://desktop.github.com/) и войдите в свой аккаунт.
2. `File → Add local repository…` → выберите папку `stockroom-kids`.
3. Если Git ещё не инициализирован, программа предложит `create a repository` — согласитесь.
4. Нажмите `Publish repository`, имя `stockroom-kids`, включите `Keep this code private`.
5. `Push origin` — код уйдёт на GitHub.

В репозиторий не попадут `data/`, `storage/uploads/`, `backups/`, `keystore/` и APK — это исключено в `.gitignore`.

## Шаг 2. Создать сервис на Render

1. Зарегистрируйтесь на [render.com](https://render.com) через GitHub.
2. `New → Blueprint`.
3. Выберите репозиторий `stockroom-kids`. Render прочитает `render.yaml`.
4. Проверьте план: `Starter` — он нужен для постоянного диска. На бесплатном плане диск не подключается, и база будет обнуляться при каждом перезапуске.
5. Нажмите `Apply` и дождитесь сборки (5–10 минут).

Render создаст:

- веб-сервис с HTTPS-адресом вида `https://stockroom-kids-xxxx.onrender.com`;
- диск 1 ГБ, смонтированный в `/data` — там база `stockroom.db` и фотографии товаров.

При первом запуске контейнер сам применяет миграции и создаёт учётные записи.

## Шаг 3. Войти

Откройте выданный адрес и войдите под нужной ролью:

| Логин | Пароль | Роль | Что доступно |
| --- | --- | --- | --- |
| `owner` | `Owner#2026` | Владелец (Россия) | всё: закупки, приёмка, цены, продажи, себестоимость, отчёты, сотрудники, настройки |
| `buyer` | `Buyer#2026` | Закупщик (Китай) | каталог, поставщики, закупки, приёмка, склад, себестоимость, отчёты по закупкам |
| `admin` | `Admin#2026` | Администратор | просмотр каталога, закупок, приёмок, склада и отчётов по закупкам; без продаж, цен, себестоимости, сотрудников и настроек |

После первого входа смените все три пароля: «Настройки → Смена пароля» для себя и «Сотрудники → Изменить» для остальных. Пароли из таблицы опубликованы в документации, поэтому для рабочего магазина они недопустимы.

## Как работает синхронизация

1. Все пользователи ходят на один адрес Render.
2. Сервер держит одну базу SQLite на постоянном диске.
3. Любое действие (закупка, приёмка, продажа, возврат) сразу записывается в базу и видно остальным после обновления страницы.
4. Сессия живёт 12 часов, затем нужно войти заново.
5. Одновременные операции защищены транзакциями: две продажи последней единицы не создадут отрицательный остаток.

## Обновления

1. Меняете код локально.
2. В GitHub Desktop: `Commit` → `Push origin`.
3. GitHub Actions прогоняет тесты. Если тесты зелёные, Render пересобирает сервис автоматически (`autoDeploy: true`).

Если хотите запускать деплой только после тестов, добавьте в GitHub секрет `RENDER_DEPLOY_HOOK` (Render → Settings → Deploy Hook) — workflow вызовет его вручную.

## Доступ из Китая

Сервис Render во Франкфурте обычно открывается из Китая, но скорость зависит от провайдера. Проверьте с телефона закупщика до начала работы:

- если открывается медленно, подключите свой домен через Cloudflare (Render → Settings → Custom Domain) — это часто ускоряет и стабилизирует доступ;
- если остаётся нестабильно, альтернатива — сервер в Гонконге или Сингапуре (например, VPS) с тем же Docker-образом.

## Резервные копии

- Render делает снимки диска на платных планах — уточните периодичность в тарифах.
- Вручную: Render → Shell → `node scripts/backup.mjs` создаст копию в `/data/backups`.
- Дополнительно раз в неделю выгружайте CSV из разделов «Отчёты» — это независимая копия учёта.

## Стоимость

- Render Starter + диск 1 ГБ — порядка 7–9 $ в месяц, точную цену показывает калькулятор Render при создании сервиса.
- Бесплатный план Render не подходит: сервис засыпает и теряет диск.

Если платить не хочется, остаётся схема «домашний компьютер + туннель» (`start-public.cmd`): она бесплатна, но зависит от включённого компьютера и меняет адрес при перезапуске.

## Проверка после деплоя

1. `https://<адрес>/api/health` возвращает `{"ok":true}`.
2. Вход владельцем открывает главную панель.
3. Вход закупщиком не показывает прибыль и продажи.
4. Вход администратором не показывает себестоимость и не даёт создать продажу.
5. Созданная владельцем закупка видна закупщику после обновления страницы.
