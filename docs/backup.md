# Резервное копирование и восстановление

## Что копируется

| Объект | Путь | Примечание |
| --- | --- | --- |
| База данных | `data/stockroom.db` | основной файл; в режиме WAL рядом могут быть `-wal` и `-shm` |
| Фотографии товаров | `storage/uploads/` | имена файлов хранятся в `products.photo_path` |

Копировать `stockroom.db` вручную при работающем сервере не рекомендуется: часть данных может находиться в WAL. Штатный способ — команда `VACUUM INTO`, которая снимает согласованный снимок без остановки приложения.

## Резервная копия

```powershell
node scripts/backup.mjs
```

Скрипт:

1. Открывает текущую базу.
2. Выполняет `VACUUM INTO backups/stockroom-<дата>-<время>.db`.
3. Проверяет копию через `PRAGMA integrity_check`.
4. Печатает путь и размер файла.

Копии складываются в `backups/`. Фотографии копируются отдельно:

```powershell
Copy-Item -Recurse -Force storage\uploads backups\uploads-<дата>
```

Рекомендуемый режим: ежедневная копия в конце рабочего дня, хранение не менее 30 дней, одна копия вне компьютера магазина (сетевой диск или защищённое облако). Перед крупными операциями — инвентаризацией, массовым импортом каталога — копия снимается дополнительно.

## Проверка восстановления

Проверку нужно проводить не реже раза в квартал, на отдельном каталоге:

```powershell
# 1. Временный каталог данных
$env:SRK_DATA_DIR = "C:\StockroomKids-test"

# 2. Скопировать файл копии как рабочую базу
New-Item -ItemType Directory -Force C:\StockroomKids-test | Out-Null
Copy-Item backups\stockroom-2026-10-17-18-00-00.db C:\StockroomKids-test\stockroom.db

# 3. Запустить приложение на другом порту
$env:PORT = "3100"
node src/server.mjs
```

Открыть `http://127.0.0.1:3100`, войти под владельцем и проверить: количество товаров, остатки, последнюю продажу, отчёт по закупкам. Совпадение с рабочей системой означает, что копия пригодна.

## Восстановление рабочей системы

1. Предупредить сотрудников и остановить сервер (`Ctrl+C` в окне приложения).
2. Сделать копию текущего состояния: `Copy-Item data\stockroom.db data\stockroom-before-restore.db`.
3. Заменить рабочую базу: `Copy-Item <файл-копии> data\stockroom.db -Force`.
4. Удалить устаревшие `data\stockroom.db-wal` и `data\stockroom.db-shm`, если они остались от прежней базы.
5. Восстановить фотографии из копии `storage/uploads`, если они утрачены.
6. Запустить сервер и проверить: вход, главная панель, остатки, последняя продажа.
7. Зафиксировать факт восстановления в журнале эксплуатации.

## Ограничения

- Автоматического расписания внутри приложения нет: копирование запускается вручную или планировщиком Windows.
- Восстановление возвращает состояние на момент копии: документы, созданные после, будут потеряны. Их следует повторно внести по первичным документам.
- Пароли в копии хранятся в виде scrypt-хешей; при передаче копии третьим лицам её нужно шифровать.
