# Android-приложение

Приложение `Stockroom Kids` для Android — нативная оболочка (Capacitor) вокруг того же веб-интерфейса. Код интерфейса и учётной логики не дублируется: приложение открывает ваш сервер, поэтому все функции, остатки, права и отчёты совпадают с веб-версией.

## Файлы

| Что | Где |
| --- | --- |
| Готовый APK | `mobile/apk/stockroom-kids-1.1.apk` |
| Отладочный APK | `mobile/apk/stockroom-kids-1.1-debug.apk` |
| Исходники оболочки | `mobile/` (экран запуска — `mobile/www/index.html`) |
| Android-проект | `mobile/android/` |
| Ключ подписи | `mobile/keystore/srk-release.jks` + `mobile/keystore/keystore.properties` |

Ключ подписи нужно сохранить: без него нельзя выпускать обновления поверх установленной версии. Пароль хранится в `keystore.properties`, в репозиторий и в переписку его выкладывать не следует.

## Установка на телефон

1. Передайте `stockroom-kids-1.0.apk` на телефон (кабель, облако, Telegram «Избранное»).
2. Откройте файл. Android спросит разрешение на установку из этого источника — разрешите для файлового менеджера или мессенджера.
3. Запустите «Stockroom Kids».
4. Введите адрес сервера вида `http://192.168.0.104:3000` и нажмите «Подключиться».
   - Адрес показывает компьютер: «Настройки → Состояние системы → Адрес для телефона».
   - Телефон и компьютер должны быть в одной сети Wi-Fi.
5. После проверки связи откроется обычный экран входа. Логин и пароль — те же, что в веб-версии.

Адрес запоминается. При следующем запуске приложение само проверяет сервер и сразу открывает систему; если сервер недоступен, показывается понятное сообщение и поле для смены адреса.

## Если телефон пишет «сервер не отвечает»

Проверяйте по порядку:

1. **Сервер слушает только сам компьютер.** Запускать нужно через `start-server.cmd` в папке проекта: он выставляет `HOST=0.0.0.0` и печатает адрес для телефона. Команда `node src/server.mjs` без переменной `HOST` доступна только с этого компьютера.
2. **Адрес изменился.** IP компьютера выдаёт роутер; проверьте его в окне сервера или командой `ipconfig`. В приложении нажмите «Изменить адрес».
3. **Телефон в другой сети.** Нужен тот же роутер по Wi-Fi, не мобильный интернет и не гостевая сеть с изоляцией клиентов.
4. **Брандмауэр Windows.** Порт 3000 должен быть разрешён для `node.exe`. Если правило отсутствует, добавьте его от имени администратора:
   ```powershell
   New-NetFirewallRule -DisplayName "Stockroom Kids 3000" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 3000 -Profile Any
   ```
5. **Проверка с компьютера.** Откройте в браузере `http://<IP компьютера>:3000` — если страница входа открывается, сервер и порт в порядке, проблема в сети телефона.

## Сборка

Требования: JDK 17 и Android SDK (platform 34, build-tools 34.0.0).

```powershell
$env:JAVA_HOME = "$env:LOCALAPPDATA\StockroomKids\toolchain\jdk17"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\StockroomKids\toolchain\android-sdk"

# обновить веб-экран запуска и конфигурацию
node .\node_modules\@capacitor\cli\bin\capacitor sync android

# debug-сборка
.\android\gradlew.bat -p android assembleDebug

# release-сборка с подписью
.\android\gradlew.bat -p android assembleRelease
```

Готовые файлы:

- `android/app/build/outputs/apk/debug/app-debug.apk`
- `android/app/build/outputs/apk/release/app-release.apk`

Иконки и заставки пересобираются скриптом:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\make-icons.ps1
```

## Выпуск обновления

1. Увеличьте `versionCode` и `versionName` в `android/app/build.gradle`.
2. Соберите `assembleRelease` тем же ключом `srk-release.jks`.
3. Установите новый APK поверх старого — данные и сессии сохранятся.

## Технические детали

- Идентификатор приложения: `ru.stockroomkids.app`.
- Минимальная версия Android: 5.1 (API 22), целевая — Android 14 (API 34).
- Разрешён HTTP без TLS (`usesCleartextTraffic`), потому что магазин работает в локальной сети; для публичного адреса используйте HTTPS.
- Навигация на любой адрес сервера разрешена внутри приложения (`allowNavigation: ["*"]`).
- Экран запуска проверяет `GET /api/health`; сервер отдаёт для этого эндпоинта CORS-заголовок, остальные запросы идут с того же домена, что и интерфейс, поэтому cookie-сессия работает как в браузере.
- Приложение не хранит копию базы: все данные остаются на сервере магазина.

## Ограничения

- Без доступного сервера приложение не работает: это клиент, а не автономная база.
- Публикация в RuStore/Google Play требует release-сборки, подписи, политики конфиденциальности и описания приложения; APK для внутреннего использования готов.
- Push-уведомления и офлайн-продажи не реализованы — как и в веб-версии.
- При смене адреса сервера нужно нажать «Изменить адрес» на экране запуска.
