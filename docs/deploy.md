# Развёртывание

## Вариант 1. Компьютер магазина (пилот)

Подходит для одного магазина и 2–5 сотрудников в локальной сети.

1. Установить Node.js 24 LTS (или использовать портативную сборку).
2. Скопировать папку проекта, например в `C:\StockroomKids`.
3. Выполнить `node src/seed.mjs` — создаётся база, роли и три учётные записи.
4. Запустить `node src/server.mjs`.
5. Для доступа с телефонов и планшетов той же сети задать `HOST=0.0.0.0` и открыть в браузере адрес компьютера, например `http://192.168.1.20:3000`.
6. Сменить демонстрационные пароли, создать сотрудников, заполнить каталог.

Автозапуск при входе в Windows:

```powershell
$action = New-ScheduledTaskAction -Execute "C:\Program Files\nodejs\node.exe" `
  -Argument "src/server.mjs" -WorkingDirectory "C:\StockroomKids"
$trigger = New-ScheduledTaskTrigger -AtLogOn
Register-ScheduledTask -TaskName "StockroomKids" -Action $action -Trigger $trigger
```

Логи приложения при таком запуске не сохраняются; для диагностики удобнее запускать из окна терминала или перенаправлять вывод в файл.

## Вариант 2. Сервер с HTTPS (доступ из Китая и из магазина)

Требования ТЗ: проверить сетевую доступность хостинга одновременно из магазина и из Китая. Размещение сервера само по себе этого не гарантирует.

Минимальная схема:

1. Виртуальный сервер с Node.js 24, каталогом приложения и постоянным диском для `data/` и `storage/uploads`.
2. Обратный прокси (nginx или Caddy) с TLS-сертификатом, проксирующий на `127.0.0.1:3000`.
3. Приложение слушает только `127.0.0.1`, наружу выходит только прокси.
4. Резервные копии — по расписанию, с выгрузкой за пределы сервера.

Пример конфигурации Caddy:

```
stock.example.ru {
    encode gzip
    reverse_proxy 127.0.0.1:3000
}
```

Пример systemd-юнита:

```ini
[Unit]
Description=Stockroom Kids
After=network.target

[Service]
WorkingDirectory=/opt/stockroom-kids
ExecStart=/usr/bin/node src/server.mjs
Environment=PORT=3000
Environment=HOST=127.0.0.1
Environment=SRK_DATA_DIR=/var/lib/stockroom-kids
Restart=always
User=stockroom

[Install]
WantedBy=multi-user.target
```

## Чек-лист перед реальным учётом

- [ ] Сменены пароли всех учётных записей, демонстрационные отключены.
- [ ] Созданы сотрудники с нужными ролями, проверен доступ каждого.
- [ ] Настроено резервное копирование и **проверено восстановление** на отдельном каталоге.
- [ ] Заполнены категории, поставщики, каталог с размерами и ценами.
- [ ] Согласованы правила распределения расходов и порядок учёта партий.
- [ ] Определены требования к кассовому оформлению продаж (вне системы).
- [ ] Проверена доступность адреса из магазина и от закупщика.
- [ ] Прогнаны приёмочные тесты на рабочей версии: `node tests/acceptance.mjs`.

## Обновление версии

1. Снять резервную копию: `node scripts/backup.mjs`.
2. Остановить приложение.
3. Заменить файлы `src/`, `public/`, `tests/`, `scripts/`.
4. Запустить приложение: миграции применяются автоматически при старте.
5. Проверить вход, главную панель, остатки и последнюю продажу.

## Ограничения эксплуатации

- Один экземпляр приложения на файл базы; второй процесс на ту же базу запускать не следует.
- Файлы `data/` и `storage/uploads/` должны находиться на постоянном диске, а не во временном слое контейнера.
- Порт наружу не публикуется без HTTPS: cookie сессии передаётся по сети и должна быть защищена транспортом.
